# Music Learning

以音乐工程为共同上下文，让用户与 AI 一起研究、改编、积累并创作音乐。

主要流程：**主页选择音乐 → 整曲预处理 → 专用工作台 → 全曲或局部讨论 → 修改与试听 → 保存经验 → 跨工程创作**。

用户具备较好的乐理基础。产品围绕具体作品展开和声、声部进行、配器、节奏与曲式讨论，支持直接修改音乐并比较听感。

## 当前状态

2026-10-18：完成产品与开发规划，初始化本地 Git 仓库。当前仓库仅包含文档与仓库配置，尚未实现应用、安装模型或验证实际转录效果。

第一阶段目标：一首完整音乐完成预处理后，用户能够在专用前端定位任意片段，与 AI 讨论，完成一次局部改编、试听比较，并在重启后继续工作。

## 第一阶段技术基线

- Windows 本地运行，浏览器访问专用前端。
- React、TypeScript、Vite；Canvas 时间线与钢琴卷帘；Web Audio 统一播放时钟。
- Python 3.11、FastAPI、Pydantic；SQLite 元数据和磁盘文件；独立任务进程。
- MuScriptor 多乐器转录、Demucs 分轨、SheetSage2 和声及结构分析，分别通过可替换适配器接入。
- FluidSynth 与固定 SoundFont 渲染重建音乐；FFmpeg 负责解码、转换与混音。
- AI 通过结构化工具读取工程、生成编辑事务、请求渲染；具体供应商与音乐模型解耦。

以上是开发基线。模型兼容性、音质、耗时与对话服务接入将在 P0 验证，随后锁定具体依赖及权重版本。

## 仓库与音乐工程

Git 管理源代码、开发文档、契约和小型测试数据。用户音乐、模型、分轨、渲染音频、数据库、对话与个人经验保存在被忽略的 `data/`、`models/`、`runtime/` 中，并由应用自己的工程版本与备份机制管理。

本地 Git 仓库不等于远程备份；音乐工程也不依赖 Git 提交来保存。
