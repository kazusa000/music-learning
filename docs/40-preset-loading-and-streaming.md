# 音色切换与连续供声

2026-10-20。对应新增轨道等待、Wurlitzer 断续噼啪、换音色缓慢，以及内置 AI 的多余限制。

## 实际原因与修改

浏览器原先只提前供应 240ms PCM。独立真实浏览器中，让界面繁忙 500ms 后出现 4 次缺声，跳过 12,402 帧，最大迟到约 215ms。同一流程改为提前供应 1 秒后，缺声、跳帧均为 0。首次拿到 PCM 即启动，随后填充余量；本次首次声音观测旧 42.4ms、新 31.9ms，并非增加一秒启动等待。推子、静音和独奏仍在浏览器 gain 节点直接生效，不等待未来 PCM、不提交音频任务。新增缺声计数只在调试 DOM 中回读，不增加面向用户的提示栏。

原生子进程不是声卡回调，而是在浏览器播放时钟前生成小块 PCM。此前统一 setNonRealtime(false) 会让 Keyscape 的采样工作异步返回；某些钢琴即使状态和 MIDI 通道正确，也可能输出近零 PCM。现在只对已经识别的 Keyscape 1.3.3d 使用完成每块采样工作的模式，其余插件仍保留原模式。只修改 additive live-track 宿主；原离线宿主、音源文件与全库验证代码不改。这不是生成整曲 WAV，也不是在 Python 中做实时回调。

原 Wurlitzer 对话共约 161 秒，其中 instrument.capture 约 123 秒：已有入库验证仍重新实例化插件、生成首次/恢复两份短试听。新增 preset_import.py：优先复用本工程当前 head 或手动保存版本内的原厂完整状态；否则读取音色库已通过首次及恢复验证的完整原生状态，核对入库 state/probe、验证收据、资源和插件身份后发布小型状态/描述/依赖。复用时恢复描述中原厂参数基线，不带入用户后来调过的参数。素材只在当前工程或手动版本需要时保留，不重新保活全部历史音色。没有可用完整状态的旧入库预设、尚未验证的音色以及其他格式继续使用原有首次捕获流程；不能把仅有预设名称当成已有完整状态。

读取标准 VST3 源文件用于检查 class ID 与资源，实际应用的是已验证的完整原生 component/controller 状态。调试中直接包装原厂 Comp/Cont、以及使用独立诊断宿主的静音结果均被拒绝，未作为成功发布。最终也没有采用重复渲染一次或两次测试音频的优化分支；音色复用不生成新的 WAV。

空 MIDI 轨道不再列为缺失声音，不为它启动一个只产静音的原生进程。前端新增空轨道的立即反馈、工作状态回执与后台派生刷新见文档 39。

新宿主另实测当前 Wurlitzer 状态复用约3.77秒、再次0.73秒，冷装47.13秒，RMS 0.00939、peak 0.08531。速度优化移除了重复验证，但没有消除插件自身加载或磁盘竞争成本。

## 内置 AI 操作规则

删除每轮只能提交一次编辑和 32 次工具调用上限。每次成功编辑后读取新的工程 revision，同轮可以继续新增轨道、写入音符、修改音色。自动 scope 在每次提交时覆盖当前工程及本批新增轨道；显式 SDK read_only/edit_scope 保持原语义。多批回执记录在原 arrangements payload 的 batches 中，没有新增迁移或平行写入通道。

用户在模型工作期间从其他入口修改 head 时，后续批次仍拒绝覆盖。幂等键绑定轮次与当前批次基线，旧请求仍回放旧收据；租约、项目归属、素材 SHA、参数类型和音乐范围校验保留。默认自动模式不要求用户选择权限，不因讨论片段限制整轨换音色。不改音符、音色就不创建改编事务；显式保存版本和显式导出含义不变。统一接口仍为 70 操作、11 类任务。

## 实测

隔离工程使用正式歌曲的钢琴声部副本，原 MIDI 通道 5、823 音符保持，通过播放适配为插件有效通道 1。正式工程只读，不代替用户修改或保存版本。

- 复用当前 Wurlitzer 完整状态的任务约 1.64 秒、再次约 0.73 秒，无新的 probe_asset、WAV 或整曲任务；原正式宿主冷装约 13.77 秒，230 秒处实际 RMS 0.00910、peak 0.07910。
- 从音色库的首次/恢复验证结果读取另一款 LA Custom C7 Grand Piano，约 3.56 秒、再次复用约 0.77 秒。修正后的常驻宿主冷装约 15.39 秒，230 秒处实际 RMS 0.00338、peak 0.04597。修改前同一状态在实时模式下输出近零；修正后满足 RMS > 1e-6 且 peak > 1e-5。
- 原 Wurlitzer 230 秒起约 6 秒诊断峰值 0.19944，削波数 0，最大相邻采样差 0.02105，块边界差 0.00934；这与浏览器可复现的供声缺口分别核对，不能用无削波证明没有断流。

时间为本机观测，状态复用与实际插件冷加载分别计时。Keyscape 的冷加载通常仍有约十几秒成本，本次并发验证中 Wurlitzer 还观测到 47.13 秒，尚未实现原生实例间的预加载交接或零等待切换。缓冲修正证明能吸收本次 500ms 界面停顿，不宣称能抵抗任意长度停顿，也不等于人工听辨全部通过。

187 项后端全量回归通过；覆盖多批修改、超过 32 次查询、新增轨道后继续编辑及外部 head 冲突、入库完整状态和资源变化拒绝、空轨播放计划。原生模式修改后相关回归45项通过，另1项 plugin.inspect 在并发真实加载时失败，独立重跑通过；不把首次失败隐藏为全绿。TypeScript、Vite、transport-start、levels-solo、live-mix、audition-sync 与契约漂移检查通过；transport-start 还直接回归 500ms 停顿的旧/新供声差异。
