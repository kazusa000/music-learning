## 整曲摘要来自哪里

摘要不是上传音频后直接生成的文本。整曲预处理先保存声部/音符、节拍、和弦、段落等工程数据。用户发问后，AI 的 music_query(summary) 对固定版本/范围计算音符数、音域、起音密度、音级分布、声部统计，并平衡读取各类标注、插件配置等；需要细节时再分页查询局部事件/注释或已有音频测量。AI 根据这些数据作乐理解释。统计覆盖指定范围，单次摘要只采样部分标注，不能把返回的少量标注理解成全曲仅有这些和弦。对话链路目前没有发送原音频。

此前系统提示词、每次查询返回的 notice、笔记 UI 状态同时强调候选/审核，造成重复的防御性措辞。本次删除查询 notice，将提示词改成自然直接的音乐讨论；仅在确有缺失或矛盾时说明具体问题，不再使用统一免责声明或反复复述历史中的此类标题。笔记只显示“我的笔记/AI 笔记”，现有来源和内部状态不伪造为人工确认。旧原始回复不重写，前端把已知的重复标题“依据工程候选标注的和声解读”显示为“和声解读”。工作台重复的候选/待核对提示也移除；实际失败继续报错。

## 模型

dialogue.models(login_mode,refresh) 从固定版本的本机 Codex App Server 调用 account/read 和分页 model/list，只发现模型，不启动 thread/turn，不触发推理。按登录方式缓存 5 分钟，刷新按钮可显式绕过缓存；没有放到页面启动前置路径或 SQLite 事务里。前端在模型下拉框聚焦或点击刷新时读取列表。选择的模型保存进轮次，并实际传给 thread/start；不存在或不可用时明确失败，不自动换模型。回复显示实际使用模型。

本机实际读取已有登录，返回 7 个模型，包括当前默认 GPT-6.1-Sol；没有写死这些名称到产品列表，也未为本次验证启动生成。接口依据已检索并打开 [OpenAI App Server 官方文档](https://learn.chatgpt.com/docs/app-server)，执行以本项目固定 0.163.0-alpha.10.2 的实际发现为准，未修改全局 Codex 配置或复制凭据。没有可用 openai-platform-api-key 工具；继续使用用户已授权的 managed login。

当前为 **55 项领域操作、11 类任务**，契约已导出；SDK 通用 Client.call、discuss 的 selection 参数和 CLI 可传 session_id/model。Schema 0007 纳入备份版本识别，旧归档仍可独立恢复升级。

## 文本显示

使用 react-markdown 10.1.0 + remark-gfm 4.0.1（MIT，已锁版本）渲染对话和笔记：标题、加粗、列表、表格、引用、代码块等。有效的 music://citation 链接继续按具体版本定位，外部链接单独打开。原始 HTML 不执行，非允许协议链接不生效，图片不会主动发起外部请求。流式未闭合 Markdown 由解析器持续处理，不把整段文本作为原始 HTML 注入。来源/权限/事务约束保持。
