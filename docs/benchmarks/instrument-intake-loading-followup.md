Kontakt 的本轮 157 秒加载探针在用户提示磁盘繁忙后停止，仅停止本轮创建且 PID、创建时间、命令行均匹配的进程，记录为 `cancelled_io_pressure`。没有禁用系统注入模块、修改插件、跳过产品初始化或处理授权文件。旧 SDK 结果仍保留，但其证据范围已在本记录更正。

H 盘为 USB 机械硬盘。本轮 Windows 计数先后观察到空闲 0%、队列 30；后续仍为忙碌 100%、队列 9。真实维护入口再测为忙碌 100%、队列 5、约 41.7 MB/s 写入，返回 `deferred / io_pressure`，没有启动插件、改 InstDir 或访问大采样。这些是采样时刻的状态，不作为持续速率或完成时间估算。

## 共享规则

- `instrument_probe_budget.py` 只供维护探针使用：读取 Windows 磁盘计数，默认连续三次空闲才允许开始；繁忙或无法取得计数就延后。不会阻塞产品播放，也不会无限等待、自动反复重试。
- 三个维护入口共用预算检查。宿主加载超时返回 `inconclusive / loading_timeout`，保留原始诊断；明确的非零、状态和型号身份检查不放宽，原来的静音/身份失败不重分类成通过。
- `ample_library.py` 共用 ASCF 编号连续性、非空、对应索引及歧义检查。唯一精确的 `.cf.txt` 可在准备阶段复制为规范 `.cf`；歧义索引拒绝。只在 `H:\music\Sound Library\.staging` 新目录准备，同卷采样硬链接、仅小索引复制，失败保留部分准备日志；不改源、配置或正式目录。预检不等于采样完整性或发声通过。
- 本轮 LP 独立准备目录为 `H:\music\Sound Library\.staging\20261021-ample\AGLP-4.0.0-index-normalized`，358 份采样硬链接、5 份规范索引副本，无整库复制。准备完成而非入库完成；当前源仍被硬链接引用，不能当可独立迁移的最终库。
- `modo_bass_resources.py` 只查询四个资源注册项，检查预期布局和最多八字节 PAK 头；x64 注册为准，不要求存在 x86 安装。`members_verified=False` 明确表示尚未检验模型成员。此预检接入 MODO 隔离入口，不处理许可，也不对单个型号改名或跳过身份校验。
- `native/tests/PluginWaitProbe.cpp` 只取自己创建的子宿主线程栈，超时结束该子进程，不枚举或停止正式工程进程。独立构建和调用证据留在本轮维护目录，不替换固定宿主。
