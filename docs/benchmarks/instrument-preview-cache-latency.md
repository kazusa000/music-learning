# 已缓存音色试听延迟修复

2026-10-24，用户报告 CP11 型号点击试听后长时间停在“正在准备试听”。三款 CP11 变体已有 ready 音频，缓存指纹与当前音源条目相同，不是重新制作。

## 原因与行为

原 `InstrumentPreviews.prepare` 在查询 ready 之前执行 `validate_entry`；命中 ready 后又调用 `audio`，后者重复执行源文件检查。前端随后调用 `engine.preview`，也会经过 `audio`。一次本地剖析确认单轮源检查约 3.99 秒，其中 Kontakt 已安装库检查约 3.69 秒，遍历 3707 个文件并产生约 4 万次文件状态查询。真实产品 prepare 接口即使命中缓存仍耗时 7.29 秒。

共享规则改为：按当前目录条目与既有试听指纹查缓存，ready 分支不检查采样库和插件资源，读取本地 WAV；缓存音频的 SHA、队列 ready 状态和指纹检查保留。缓存缺失或身份变化仍执行源文件检查，实际制作前后与音色应用的完整状态/参数/资源检查不变。未改变音频内容、缓存 ID、入库标准或原验证结果。

## 验证与发布

- 47 项试听/完整状态/加载专项回归及 2 项原生试听集成回归通过，Ruff 通过。新增覆盖服务重新创建后、源采样文件不可访问时缓存仍可播放，以及目录身份改变时不得绕过新制作的源校验；原损坏 WAV 拒绝与重试回归保留。
- 独立发布 `c924c81aa5e57c3d0628e6f91f13a54a755a1ff1` 只在当时当前发布 `c72d9f1` 上覆盖共享试听模块和对应测试。前端、原生引擎及桌面包保持原指纹；没有将开发树其他变化混入发布。
- 真实产品三款 CP11 缓存 prepare 分别约 1.57 / 0.97 / 1.25 秒，音频 HTTP GET 约 15 / 126 / 22 毫秒，均 ready、cached=true、HTTP 200、882044 字节。三款沿用原缓存 ID，没有生成新试听。剩余 prepare 时间包含现有约 102 MB 音源目录的读取与解析，不宣称已做到毫秒级点击响应。
- 在播放、试听与任务空闲时更新后台，保留桌面窗口，并恢复用户原有暂停的运行会话、位置与监听值。正式九表/head 前后相同。Kontakt 入库已停止状态和 Ample/MODO 取消状态不变。

维护证据位于 `runtime/maintenance/preview-cache-fastpath-20261024`，含 `before.json`、候选剖析、独立发布描述、`engine-before-restart.json` 和 `after.json`。本轮覆盖实际 SDK/API 缓存响应与音频读取及隔离原生回归，未使用 Computer Use，不以此冒充人工界面听辨。
