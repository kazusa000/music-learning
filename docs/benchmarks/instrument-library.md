## 2026-10-24 打开速度与插件显示修正

原调用路径确有产品开销：每次换预设关闭并重新创建宿主、重复读取分类目录与检查整套安装清单，Keyscape 还固定等待 10 秒。修正为同一插件身份内原位加载，缓存原子发布的目录，日常只核对选中资源与二进制，去掉固定等待和重复二进制摘要读取；没有改变音源入库器的完整验证。

首次诊断测得目录解析约 0.70 秒，旧路径三类资源检查约 0.69／1.16／3.36 秒，后续一次 Kontakt 完整清单遍历达到 7 秒。新路径桌面实测选中资源核对约 5–28 毫秒；这些是本机当时缓存／磁盘条件下的结果，不是冷盘承诺。插件自身实例化与采样读取仍单独计时。

build-25 的四项真实检查通过：三个产品的桌面原生挂载、缩放、MIDI 音频和原位切预设，以及 Keyscape 的控制器音量、保存、销毁与个人预设新实例恢复。该轮 UI 切换约 Keyscape 0.77 秒、Pianoteq 0.24 秒、Kontakt 0.68 秒，PID 与会话均保持不变。Keyscape 初次试弹等待实际发声约 1.92 秒、对应进程继续读取约 12.55 MB；个人状态恢复后约 1.58 秒、读取约 24.21 MB。此为隔离测试记录，不在产品中播放探测音符，也不把设备就绪称作所有样本读完。

Keyscape 原 1160×670 的编辑器在 4K 桌面成为 2900×1675；Pianoteq 与 Kontakt 的已测窗口分别为 1822×1780、3368×1698。旧 Keyscape 忽略标准 VST3 内容缩放，采用真正的 Windows mixed-DPI 子窗口兼容方式，原始素材清晰度不能通过宿主凭空增加。其它插件继续使用自身编辑器。原生像素截图仍受 GPU／HWND 捕获限制，几何、父子窗口、真实 MIDI 与回调音频是本次自动化证据；没有声称逐个鼠标拖动了厂商的全部控件。

试弹键盘展开时也验证 Keyscape 保持大界面且完整可见：插件页使用紧凑横条，图片页的完整钢琴不改。原始大小、适应窗口与当前插件支持的倍率在顶栏选择；无法处理原生倍率的旧界面不展示无效选项。
