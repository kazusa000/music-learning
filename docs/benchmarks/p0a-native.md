# P0a 原生宿主验证记录

日期：2026-10-18。范围：Windows x64 原生 VST3、程序化制作、处理时序、状态恢复和子进程隔离。结果基于本次真实构建与运行，不包含模型扒谱或前端验收。

## 已锁定环境

| 项目 | 本次版本 |
| --- | --- |
| Python | 3.11.15，项目本地环境 |
| CMake / Ninja | 4.4.4 / 1.13.2，Python 包及哈希锁文件 |
| MSVC | 工具目录 14.44.35207，cl 19.44.35229.0 |
| Windows SDK | 10.0.26100.0 |
| JUCE | 9.0.4，headless VST3 格式；源码未修改 |
| 真实插件 | Surge XT 1.3.4、CHOW Tape Model 2.11.4、sfizz 1.2.3 |

下载来源与文件摘要在 [依赖清单](../../config/native-dependencies.json)。微软渠道条目中的 VS manifest 摘要与实际 HTTP 文件字节不同；两次独立下载返回同一实际摘要，清单同时保留渠道声明与实际字节摘要，bootstrap 按实际字节固定内容，编译器/SDK payload 仍按微软清单的各自摘要验证。

先行 MinGW 探测被 JUCE 9 的显式平台检查拒绝，因此改用便携 MSVC/SDK，没有修改框架绕过编译器要求。构建与插件均处于本项目隔离目录。

## 测试结果

`CTest`：1/1 通过。`pytest tests/native`：**13/13 通过，14.80 秒**。

| 测试 | 证明范围 |
| --- | --- |
| capabilities | 无 UI 查询当前真实支持的接口与限制 |
| gain automation | 第 123 样本改变阶跃增益，已知 128 样本插件延迟补偿后边界准确 |
| MIDI offsets | 第 37 样本 note-on，第 233 样本 note-off，输出边界准确 |
| tempo / meter | 第 777 样本变速、第 1001 样本变拍传入插件并在输出对齐 |
| fixture restore | 独立进程恢复完整状态，WAV 文件逐字节相同 |
| invalid parameter | 不存在参数被拒绝，不产生输出 WAV |
| scan crash | 真实 VST3 扫描执行崩溃被隔离，后续正常扫描成功 |
| scan timeout | 真实 VST3 扫描挂起被限时终止，后续正常扫描成功 |
| Surge + CHOW | 真实乐器/效果发声，新进程恢复后公开参数一致；降低 CHOW 输出增益后实际 RMS 降低且回读对应值 |
| sfizz SFZ | 无窗口加载自制正弦采样 SFZ，恢复状态后输出差异小于 1e-5，显式尾音长度符合请求 |
| mixed audio / MIDI | 无延迟音频轨与经延迟插件的 MIDI 轨对齐求和 |
| unsupported routing | 未实现 sends 字段直接拒绝，不假装已经路由 |
| binary identity | 插件二进制摘要不匹配时拒绝加载 |

扫描故障测试使用只有二进制、没有 moduleinfo.json 的夹具，确保实际执行模块加载。正常 bundle 的元数据快速扫描本来就可以不执行插件，两者没有混为一谈。

## 原型创作实验

执行 `scripts/make_native_demo.py`，程序建立两条 Surge 轨道，其中和声轨经过 CHOW Tape，生成四小节原创合成器材料。第二版本保留全部和声事件，将贝斯四分音符改成二分音符，并在后两小节加入五度。

本次产物位于被忽略的 `reports/local/p0/demo-5b602053/`：original/modified WAV、快照、结果、调用日志和 summary。

| 项目 | 原版 | 改版 |
| --- | --- | --- |
| 帧数 / 采样率 | 432000 / 48000 | 432000 / 48000 |
| 时长（含 1 秒尾音） | 9 秒 | 9 秒 |
| peak | 0.11174449 | 0.09993000 |
| RMS | 0.01795434 | 0.01834624 |
| 削波样本 | 0 | 0 |
| 本次渲染耗时 | 3.99 秒 | 5.11 秒 |

这是宿主与改编机制的实验素材，不是原曲还原评估，也未进行主观音质听辨。它证明 AI 可以通过数据生成、改变声部、渲染与保存两版实际音频。

## 决策与后续

P0a 采用 JUCE 9.0.4 headless 宿主和受限处理图。Tracktion Engine 的高层 Edit/音序器模型与本项目的权威 revision 之间还需桥接；当前任务以无界面插件控制和离线验证为主，JUCE 已满足该范围，因此暂不引入第二套工程模型。这是接口/范围评估，没有声称完成 Tracktion 性能对比。后续复杂图和片段系统若暴露明显成本，再提交新的决策与验证。

P0a 退出条件已满足，可进入 P0b。P1 数据库/编辑事务、P3 完整路由/冻结和后续 AI 制作流程继续保留在计划中。当前测试不证明所有 VST3 兼容，也不证明完整 DAW 已完成。
