# 内置 AI 初始化超时修复

2026-11-08。工程服务正常，但现有登录下的 Codex `initialize` 没有返回；最近失败目录只有初始化请求，`TimeoutError` 的字符串又为空，界面未提供有效原因。

## 原因与修复

旧客户端让每轮进程使用全局 `CODEX_HOME`，同时将 `sqlite_home` 指向一个全新目录。Codex 在初始化前回填用户已有聊天记录：原失败状态库已有 527 条 threads，`backfill_state` 仍为 running，尚未到任何模型请求或工程工具调用就超过 30 秒。空 home 对照约 0.66 秒完成初始化；禁用技能、插件和宿主特性的独立对照未解决该状态回填问题。

客户端现在分开管理登录来源和运行状态。现有登录仅从所选 home 的 `auth.json` 只读取得，运行 home 留在应用自己的一轮目录；使用官方 `account/login/start` 与 `cli_auth_credentials_store=ephemeral` 接入内存认证，不复制全局历史，不写凭据文件，不改变原登录。ChatGPT 与 API Key 的协议均实核为内存存储，API Key 检查只使用假值、没有请求收费推理。独立登录路径保留原行为。

刷新请求仅接收 Codex 自己续期后更新的、同一账号的访问凭据；不改写全局刷新令牌、不更换账号、不无限重试同一份被拒绝的凭据。错误信息现在区分登录缺失与 RPC 阶段超时，保留阶段与秒数，回复区可显示初始化超时提示。

- 固定运行组件实际初始化、模型目录及普通／快速通道与思考强度协议检查通过，没有发送生成请求。
- 另在隔离临时目录只发送一次无工程上下文、无工具的 `Reply with only OK`。真实 `gpt-6.1-sol` 完成回复 `OK`，启动约 0.50 秒，总计约 3.52 秒；没有在正式工程写入测试对话。
- 当前登录的实际模型目录返回 8 项。原登录文件 SHA 不变，临时运行 home 没有生成 `auth.json`。这与仅凭目录判断账号可推理的检查分开记录。

失败对照和原始私有日志保留，小报告在 `runtime/maintenance/ai-connectivity-20261108`。测试经统一入口执行，临时夹具和自有子进程退出清理；没有运行音乐模型、音源验证或正式渲染。

## 发布边界

仅切换包含修复的服务源码，沿用现有网页、原生引擎、桌面和 Studio 配套包。发布前读取实际暂停状态及正式九表保护基线，不重放旧失败消息，不修改音乐版本；实际生效版本以 `runtime/application-release.local.json` 为准，最终核对和产品 API 响应记录在本轮维护目录。

协议依据：[App Server 身份认证](https://learn.chatgpt.com/docs/app-server#authentication)、[凭据存储](https://learn.chatgpt.com/docs/auth#credential-storage)。当前实现对现有文件式登录做状态隔离；没有将凭据写进配置、源码、日志、命令行或发布包。
