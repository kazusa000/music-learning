## 完整曲目制作

使用 P2 已验证的本机副本及独立工程分叉，NAS 本轮未连接。原录音 SHA-256 仍为 `a870febc293b50604bb68ce7d50a536593ff61c18bbad4cbb9efebc36e62db43`；源工程 head 与快照摘要始终不变。

在 60～90 秒的指奏贝斯候选中，显式选择 12 个完整落在区间内的音符，删除其中 6 个，并对其余 6 个转调及降低力度。所有非目标音符逐项一致。建立独立 CHOW Tape 并行总线、-12 dB 发送和 -6 dB 总线增益，写入真实 Output Gain 线性自动化，再执行整曲渲染。

固定回放的初版混音约 75.69 秒，改动版约 92.25 秒，冻结版约 86.80 秒；串联时序修正后的宿主另完成同版本 307 秒重放，约 85.10 秒，冻结贝斯摘要仍一致。这些是本机单次结果，不外推其他插件/作品的速度。

改动版 peak=0.18227、rms=0.02438，触顶/削波采样数 0；integrated=-29.62 LUFS、true peak=-14.79 dBTP、LRA=5.1 LU。它是替代音色的学习重建，未做响度最大化，也不是原唱/原音源复刻或主观听感评分。

通过实际 HTTP 读回 10 个不同产物、974,865,239 bytes，摘要全部正确，包括完整 WAV、逐轨与 MIDI。MIDI PPQ=32760，9,372 个音符按轨回读，音高、声道、离散力度一致；tempo/meter 解码后的最大起止时值误差为 0.000006454 秒。弱起 marker 与源版本文本随新导出保留。

最后在三个工程上实际停启：源 P2 工程、最终 P3 制作工程、300 秒脉冲工程。完整准备状态逐一经 HTTP 回读摘要，重启前后 head、快照、全部版本及渲染 publication 一致。SQLite 元数据备份与包含 CAS 的全工程打包不是同一验收；后者仍留 P6。

## 时序与事务修复

原生链路不只按总延迟裁切输出，还把后级插件 MIDI/CC、自动化及 tempo/meter 上下文移到其实际收到源信号的处理时刻。两级 128 样本夹具证明音符 37/233、自动化 123、速度切换 777、拍号切换 1001 都在补偿后的指定样本生效。侧链还覆盖目标前有延迟插件的路径。

试听写入与轮询原先可能重复启动同一条命令。修正后，两条实际音轨各只启动一次，5 轮脉冲循环周期均为 48,000 样本。音频输出时间戳用于显示，处理时钟用于 A/B 调度，保留设备延迟边界。严格自动播放策略下，未激活页面通过服务回报 needs_activation；一次真实播放点击后可正常启动，不会陷入永久 loading。

版本 A/B 使用指定历史版本的已完成音频，保持位置；恢复旧版本创建新 revision，重建按钮在新版本未渲染时禁用，旧版本音频仍可回读。渲染/导出任务把隐式目标归一化为显式 revision_id；当前 head 改变后重试仍执行原任务版本，旧记录的 null 目标也按 job.revision_id 恢复。

深路径测试发现原生 JSON 外层 TemporaryFile 加 replaceWithText 内层临时文件会叠加后缀，触及 Windows 路径上限。改为单次同目录原子写入，在同等深度测试目录完成真实插件与状态回归；没有改系统长路径设置或把测试换成较短目录来掩盖问题。

## 明确边界

卷帘仍是只读查看；全部制作通过统一 API/SDK/CLI。当前 38 项操作。原曲、重建、选定声部和参考版本有明确播放方式；不能把播放意图当实际已发声。

处理图为立体声离线 DAG，发送为推子后；复杂反馈、多声道、实时演奏、厂商私有菜单/预设浏览器、未验证的不可自动化参数、物理单位参数输入和插件生成的 MIDI 路由未开放。MIDI 片段循环按显式事件/内容长度定义，跨界延音和含糊裁剪拒绝；CC 为独立轨道事件，不伪造踏板细节。

模型漏音、合并声部、鼓映射、力度/控制器缺失、分轨串音和和声/段落候选误差仍在。未重新声称模型更准确；没有人工听辨，也没有产品内真实 Codex 讨论或自然语言改编验收。P4/P5/P6 退出项尚未勾选。
