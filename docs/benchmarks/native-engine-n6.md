# N6：实时处理图与共用导出内核

2026-10-21。**N6阶段验收完成；N7进行中，正式未切换。** 整体目标继续active。实现设计见[运行图记录](../architecture/native-graph-runtime.md)。

`GraphKernel`在项目采样率执行拓扑图，主输出统一重采样。原生事件和私有共享内存连接隔离VST3节点；主输入、逐插件侧链与输出均不经Python/HTTP。设备仅消费两块预分配输出。主/发送与目标插件侧链按到达延迟补齐，预滚后移除整图延迟；自有音符、音频、自动化及tempo/meter/loop使用同一来源时间。音频重叠片段相加。崩溃或卡死节点独立诊断，严格导出遇到节点失败不会发布缺轨WAV。

兼容音符/参数增量保留进程；纯参数更新保留处理状态，播放中的无关声部不重置。暂停编辑会替换旧预取音频，再确认声音版本，前端不能把旧插件的ready当新版本完成。普通直出轨结构变化复用无关插件的现有样本序列，避免资源变化导致全轨重新触发。完整处理图定位/循环保留已加载进程。**复杂图资源替换和延迟动态重规划仍在后续收口，不据此宣称所有结构修改均无缝。**

WAV最终混音准备使用新`ml_graph_runner`，与设备生产器共用GraphKernel。导出冻结revision与独立mixing_version，不写编曲Render；原有显式已渲染素材导出仍可复制所指定素材，初始导入校准/冻结制作保留原制作宿主。新引擎、worker、runner组成SHA验证的不可变运行副本，运行中不会因下一次构建而加载另一版本worker；旧三个宿主/静态库保持原样。

校准在复杂路由主输出施加一次，不能在源轨与总线沿途反复放大。`ListeningProcessor`共用链接声道压缩（−1dB、20:1、1ms/60ms）、4倍软顶限幅、1dB余量。与当前旧浏览器实际OfflineAudioContext进行6秒三档增益比较，差−0.50/−0.50/−0.60 LU；最高档原生true peak −1.21dBTP。证据`n6/listening-v1/comparison.json`。这是三组确定性信号的算法迁移核对，**不是全曲或所有音色的人耳响度验收**。

## N6收尾

资源变化由独立准备线程加载新节点，原图继续供声；完成后只在块边界替换目标节点。旧节点/Job Object在后台释放，释放前程序路径仍列入保留清单，防止维护循环提前删资源。失败节点可在显式重试时单独重建；快速过时准备按代次取消。暂停修改由生产器/控制活动屏障更换旧预取，设备回调不等待锁。全图替换前暂停旧生产器以稳定内存预算；准备被拒绝时恢复旧生产器。

新独立`MLDynamicFixture`不覆盖原Fixture/宿主，通过真实DSP将延迟128→256样本。运行图按最新链/侧链前置延迟重新规划，必要时预滚并保持源位置；进程不重开。**总延迟变化会重新同步全图，过渡块单独记录在latency_change_blocks，不保证此类变化无缝。** 固定离线任务中插件自行改变延迟会明确失败，防止交付时轴不明的音频；静态新参数导出使用其实际初始延迟。普通相同延迟资源替换不会重触发无关声部。

预算包括父/子进程PCM、IPC、重采样、4倍峰值保护以及每个打开读器1MiB的保守格式缓冲预留；**cache_bytes是音频缓冲上界，不是进程RSS，也不包含第三方采样库**。新旧图、预览、保留插件与后台替换一起计入256MiB额度，预检不足不替换正在播放的图。测试核对一小时源时间元数据仍使用同等缓冲；真实长音频/30分钟另属N7。旧N2报告仅统计环缓冲，不能与这个上界直接当作内存涨幅比较。
