# N6：实时处理图与共用导出内核

2026-10-21。**N6核心已实现并进行独立验收，阶段尚未完成；N7未完成，正式未切换。** 整体目标继续active。实现设计与余项见[运行图记录](../architecture/native-graph-runtime.md)。

`GraphKernel`在项目采样率执行拓扑图，主输出统一重采样。原生事件和私有共享内存连接隔离VST3节点；主输入、逐插件侧链与输出均不经Python/HTTP。设备仅消费两块预分配输出。主/发送与目标插件侧链按到达延迟补齐，预滚后移除整图延迟；自有音符、音频、自动化及tempo/meter/loop使用同一来源时间。音频重叠片段相加。崩溃或卡死节点独立诊断，严格导出遇到节点失败不会发布缺轨WAV。

兼容音符/参数增量保留进程；纯参数更新保留处理状态，播放中的无关声部不重置。暂停编辑会替换旧预取音频，再确认声音版本，前端不能把旧插件的ready当新版本完成。普通直出轨结构变化复用无关插件的现有样本序列，避免资源变化导致全轨重新触发。完整处理图定位/循环保留已加载进程。**复杂图资源替换和延迟动态重规划仍在后续收口，不据此宣称所有结构修改均无缝。**

WAV最终混音准备使用新`ml_graph_runner`，与设备生产器共用GraphKernel。导出冻结revision与独立mixing_version，不写编曲Render；原有显式已渲染素材导出仍可复制所指定素材，初始导入校准/冻结制作保留原制作宿主。新引擎、worker、runner组成SHA验证的不可变运行副本，运行中不会因下一次构建而加载另一版本worker；旧三个宿主/静态库保持原样。

校准在复杂路由主输出施加一次，不能在源轨与总线沿途反复放大。`ListeningProcessor`共用链接声道压缩（−1dB、20:1、1ms/60ms）、4倍软顶限幅、1dB余量。与当前旧浏览器实际OfflineAudioContext进行6秒三档增益比较，差−0.50/−0.50/−0.60 LU；最高档原生true peak −1.21dBTP。证据`n6/listening-v1/comparison.json`。这是三组确定性信号的算法迁移核对，**不是全曲或所有音色的人耳响度验收**。

独立证据存放在`data/maintenance/native-engine/n6`，不放进正式工程：

- `node-tests-v1`：6个节点/5个原独立插件路径，共11项通过，真实MLFixture VST3侧链、128样本延迟、每采样自动化、输入所有权、参数更新历史、音符释放与崩溃/卡死。
- `combined-v2`：19项通过，增加并行/串联384样本PDC、第二个插件侧链、线性混音曲线、重复片段/发送求和、带FX的FLAC原生读取、失败导出不发布、运行副本保护与真实最终混音版本。
- 同一DAG从后台生产器/设备消费代码捕获，与严格离线输出PCM逐字节相同；该捕获没有打开物理设备，不能冒充硬件回环。
- `core-final-v1`：39过/1败，新增暂停参数测试漏写SDK显式structural范围，生产检查正确拒绝。补齐夹具后`paused-fix-v1`两项通过，实际设备路由播放/暂停编辑/循环、进程复用、无关直出轨epoch均通过。
- Ruff、TypeScript与原生transport单元通过；新单元覆盖旧ready不能完成新音色请求。
- `backend-core-v1`：当前完整后端360项通过，173.21秒。包括最终暂停编辑/循环/直接轨结构替换和共用导出；不是N7的实际整曲或回环验收。
- `core-protection-v2.json`：正式九表/head与14保护摘要相同；未重启8765、未部署候选UI。H音源只读，NAS未访问，Pianoteq固定实现与历史拒绝目录不动。

失败和中间报告原地保留：早期导出子环境引入SQLAlchemy和Windows嵌套路径过长分别由纯序列化模块/延迟导入与扁平哈希程序目录修复；一次测试期间源文件变动被implementation_changed正确拒绝，未放宽指纹。没有掩盖失败或将这些阶段结果写成N6/N7已经完成。
