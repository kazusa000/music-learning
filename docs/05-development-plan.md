# 第一阶段开发顺序

第一阶段交付：AI 能通过 API/SDK/CLI 完成完整音乐预处理、DAW 工程操作、VST3 制作、讨论、局部改编、试听比较和保存恢复。前端展示结果并承载讨论与试听；不要求 MIDI 键盘或手工 DAW 编辑流程。

截至 2026-10-18，P0a/P0b 与 P1 已完成，P2～P6 尚未开始。[P0b 报告](benchmarks/p0b-real-song-and-codex.md)记录模型质量限制；[P1 报告](benchmarks/p1-persistence.md)记录工程与任务恢复、统一接口及整曲主页验证。下一步 P2，暂不承诺未经实测的工期。

## P0 技术探测与基线锁定

先验证原生宿主和 AI 无界面操作路径，再验证整曲模型链路，产出探测脚本、测量结果与依赖清单。

### P0a 原生 VST3 与程序化制作

- [x] 建立 C++20/CMake 探测工程，验证 JUCE 宿主；比较 Tracktion Engine 的工程桥接成本与许可，记录取舍。
- [x] 自制确定性 VST3 夹具验证参数、延迟、状态和故障；独立进程扫描与超时隔离。
- [x] 在无界面点击的情况下，加载 Surge XT 与 CHOW Tape，创建乐器轨、写 MIDI、设置参数并渲染。
- [x] 读取参数/总线/能力，改参数后回读并验证声音差异；验证保存/重开、插件状态和依赖恢复。
- [x] sfizz 用自制最小 SFZ 验证无窗口加载与采样依赖；不将任意 SFZ 库视为自动兼容。
- [x] 测试音频轨与乐器轨共同处理、速度/拍号上下文、阶跃自动化、延迟补偿和显式尾音；记录离线处理限制。
- [x] 通过 CLI/结构化请求完成并留存上述全过程，前端不参与操作；无对应 API 的步骤作为缺口处理。

结果与边界见 [P0a 验证记录](benchmarks/p0a-native.md)。上述是原生处理原语，完整数据库/编辑事务、曲线自动化和复杂路由仍在后续阶段。

进入 P0b 条件：至少一个真实 VST3 乐器和一个效果器完成程序化生成、修改、渲染与重开。默认候选见[插件清单](10-free-vst3-candidates.md)，无需先安装全部候选。

### P0b 整曲分析与服务能力

- [x] 194 秒原创真值夹具 + 用户授权 NAS 的 305 秒完整歌曲；NAS 仅 rb 复制，完成后摘要/大小/mtime 一致。
- [x] 两套隔离环境，RTX 5080 实测 CUDA 运算及三个模型完整曲加载推理，无 CPU 回退。
- [x] MuScriptor medium：305 秒 61/61 块完成；194 秒夹具另做整曲与三个代表区间评分，记录漏检、声部合并、时值与力度/控制器缺失。
- [x] Demucs：完整夹具和真实录音四分轨，检查长度、对齐、客观混合残差与贝斯替换路径；没有真值的真实曲目不虚报单轨准确率。
- [x] SheetSage2：夹具 + 305 秒双窗口整曲，default FFmpeg CLI/sm_120 可用。FFmpeg Python backend 不可用，paper 预设不开放；模型时值/结构/弱起问题保留。
- [x] MuScriptor 六类声部完整映射到真实 VST3，生成 307 秒混音与六条逐轨文件，记录合成器/鼓音色替代及动态信息限制。
- [x] 3～6 分钟完整渲染与浏览器定位/循环/内存，原生和浏览器脉冲 0 样本偏移；显示时钟抽样滞后 21.33 ms。正式产品光标/设备延迟继续在 P3 验收。
- [x] Codex App Server 既有 ChatGPT 登录实测随机码工具往返、流式、错误、中断；当前只发送文本/合成工程数据，直接音乐音频理解未验证。
- [x] 原生/插件、两套 Python hash locks、固定模型/父模型/权重摘要、Codex 四文件、媒体工具版本/摘要与采样依赖已记录，bootstrap/check 回放通过。跨机发行与工程备份留在交付阶段。

交付：Git 外测量/音频，`docs/benchmarks/p0b-real-song-and-codex.md` 最新脱敏摘要，模型、Codex、媒体工具清单及包锁。

本机 P0b 大文件位于独立的 `D:\music-learning-runtime`；27 项回归与完整浏览器探测通过。P0 的探测接口可用，正式领域事务、持久化/前端、工程对话、人工校正与听辨仍按 P1～P6 实现，不将模型预测当成已校正的 DAW 工程。

退出条件：P0a 通过，三个模型与原生渲染链路有完整歌曲实测，试听与对话接口可用。若某个模块不可用，完成替代方案验证和文档修订；不能把缺失功能留到最终验收才暴露。

## P1 工程数据与持久化骨架

- [x] 创建前端、API、原生宿主、worker、SDK/CLI 和契约目录；加入锁文件与环境样例。
- [x] 实现 Project、Asset、AnalysisRun、TimingMap、Track、Clip、NoteEvent、PluginInstance、RoutingGraph、AutomationLane、Revision、Job、Conversation 模型与迁移。
- [x] 实现内容寻址素材、原子发布、工程创建/打开、版本读取与幂等写入。
- [x] 实现秒/样本/beat/小节映射与来源记录，建立弱起、变速、三连音和延音夹具。
- [x] 实现持久任务队列、事件 cursor、取消、worker 崩溃恢复。
- [x] 实现全操作命令/查询入口、能力发现、插件参数/状态回读、SDK/CLI 批处理；领域服务持有唯一权威 revision。
- [x] 提供最小主页，能导入音频、显示项目与真实任务状态。

依赖：P0 的工具链和输出形态。退出条件：工程与任务跨重启可恢复，失败/取消不破坏原素材；核心工程操作经 SDK/CLI 完成，数据约定测试通过。

证据：P1 26 项测试、P0 27 项回归；305 秒真实本地副本经主页导入/播放与 CLI/SDK 持久化，6 声部/9,378 音符/插件状态/笔记/cursor 经真实服务重启核对。P1 快照提交只保存验证后的数据，不替代 P3 制作执行。详见 [运行说明](14-project-service.md)与 [P1 报告](benchmarks/p1-persistence.md)。

## P2 整曲预处理贯通

- [ ] 实现阶段缓存、校验、重试和完整性报告。
- [ ] 生成含插件状态、资源与路由的初始 revision、每轨重建、混音、波形缓存。

- [ ] 插件扫描/实例/排序/旁通/参数/受支持预设/完整状态、总线/发送/侧链和自动化全部走统一接口。
- [ ] 原生处理图完成混音、延迟补偿、逐轨/总线导出、冻结/解冻和渲染失效传播。
- [ ] 结果前端展示整曲总览、段落/和弦/波形/MIDI、插件链和差异；支持 AI 指定定位。
- [ ] 原曲/重建试听、循环、A/B、版本保存/恢复、峰值/响度/静音等测量工具。

依赖：P2。退出条件：AI 工具可完成完整工程的查询、编辑、插件/混音操作和渲染；用户可查看试听，同步与编辑边界达到[验收目标](06-acceptance.md)。

## P4 基于音乐工程的 AI 讨论

- [ ] 右侧讨论区和请求上下文快照。
- [ ] 实现整曲摘要、事件/注释查询、片段引用、区段比较工具。
- [ ] 接入真实供应商，持久化消息和可见工具结果，支持取消、重试和连接中断。
- [ ] 回复引用可点击跳转，区分分析来源、用户修正与解释。
- [ ] 验证长歌曲上下文按需读取，不依赖把全曲音符一次塞入提示词。
- [ ] 保存带版本和范围的笔记；为经验条目保留状态和来源。

依赖：P3；服务接入已在 P0 探测。退出条件：用户可提出全曲和局部问题，回答引用存在且正确的工程位置，重启后讨论与引用仍有效。

## P5 对话改编与版本比较

- [ ] 实现对话 Agent 的编辑事务，复用 SDK/CLI 已验证的领域服务。
- [ ] 校验 expected_revision、幂等键、范围、事件归属和音乐参数。
- [ ] 完成贝斯重写、节奏稀疏化、重新配和声等有实际音符变化的用例。
- [ ] 完成自然语言选择音源/调整效果/写自动化的用例，读取真实插件能力并生成可解释参数变化。
- [ ] 编辑后自动渲染，显示事件差异、渲染状态与试听入口。
- [ ] 完成贝斯混合试听：移除原 bass stem，加入新贝斯，处理边界与尾音。
- [ ] 版本 A/B、继续修改、撤销/切换，以及过期请求冲突处理。
- [ ] 导出指定版本 MIDI/WAV，保留版本和渲染说明。

依赖：P4。退出条件：一条自然语言指令产生可检查、可试听的新版本，用户继续追问可以指向该修改，原始分析和之前版本都可访问。

- [ ] 用完整目标曲目跑主页导入到改编、保存、重启恢复全过程。
- [ ] 执行全流程无界面操作、真实插件状态恢复、故障注入、导出回读，以及结果界面/试听检查。
- [ ] 人工听辨原曲、初版重建、改编和贝斯混合试听，记录模型错误与声音问题。
- [ ] 完成工程备份/恢复演练，验证数据库与素材一致。
- [ ] 提供 Windows 启动、停止、环境诊断和日志入口；退出时回收自有进程。
- [ ] 更新运行文档、已知问题、模型/依赖清单和验收结果。

依赖：P5。退出条件：所有第一阶段必需验收项通过；剩余识别误差可见且可校正。没有目标素材或真实 AI 服务时，明确保留相应验收缺口，不能用模拟结果代替。

## 顺序与实施原则

关键路径：**P0a 原生 VST3 → P0b 整曲模型 → P1 → P2 → P3 → P4 → P5 → P6**。模块实现可根据依赖安排，阶段退出条件保持不变。

优先顺序为：无界面 VST3 制作、完整操作接口与工程状态、整曲处理、渲染与回读、AI 制作循环、结果呈现。每一步提交可审查增量，记录验证证据。

开发期间出现的新需求按是否影响第一阶段验收分类。跨工程创作、经验检索等先保留数据基础，再单独安排后续阶段，不以减少完整歌曲验收替代排期。
