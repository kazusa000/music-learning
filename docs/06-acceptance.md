# 第一阶段验收方案

完成标准以用户可执行的完整流程为准。构建通过、模型返回 MIDI、工具调用成功各自只能证明对应层次；最终需要完整歌曲的处理、讨论、修改、试听与持久化共同通过。

## 验收素材

1. 确定性自制短夹具：已知拍点、变速、弱起、三连音、跨小节延音、鼓和控制器，用于定位算法与同步错误。
2. 完整参考录音：至少一首用户目标曲风的完整歌曲，覆盖开头、中段、结尾与自然尾音。早期可用公开或自制完整曲替代探测，最终保留目标素材验证。
3. 对照素材：至少增加一首配器或节奏明显不同的完整曲，报告迁移效果；不能由两首样本推断所有音乐都准确。

测试清单记录素材摘要、时长、来源、模型版本和配置。用户音频与对话不提交 Git。

## 初始技术目标

以下是待实现的验收目标，不是当前测量结果。P0 测量后可提交有理由的调整，不能在失败后静默放宽。

| 指标 | 目标与测量方式 |
| --- | --- |
| 数据时间映射 | 自制夹具中样本/秒转换误差不超过 1 个样本；beat 往返误差不超过 1e-6 beat |
| 模型分块完整性 | 所有预定块有终态，原音频覆盖无未处理间隙；安静片段允许没有音符 |
| 派生媒体对齐 | 补偿声明偏移后，以脉冲夹具测起点误差 ≤ 1 ms；模型自身起音识别误差单独评估 |
| 多轨播放 | 5 分钟脉冲素材轨间误差 ≤ 5 ms，循环后无累计漂移；OfflineAudioContext 测量与实际浏览器播放检查分别记录 |
| 界面指针 | 前台播放位置显示与音频时钟差 ≤ 50 ms，定位后不继续绘制旧位置 |
| 编辑一致性 | 非目标事件摘要 100% 保持；失效事务零部分写入；重复请求只产生一个 revision |
| 版本绑定 | 渲染产物、引用和导出全部绑定实际 revision；过期渲染不得成为新版本的试听 |
| 恢复 | 重启后已提交版本和消息完整，未完成任务可识别并恢复/重试 |

整曲处理速度、显存、磁盘占用、局部渲染延迟和长时间播放内存由 P0 建立基线；当前不预设“实时”或固定分钟数承诺。

## 音乐质量与人工听辨

技术同步正确不代表转录音符正确。选择开头、中段、结尾各至少一个代表性四到八小节，手工建立有限参考，分别记录旋律、贝斯、和弦、拍点和主要乐器误差；没有参考的内容标记未核对。

每次验收记录下列问题及例子：漏音/多音、八度错误、延音错误、拍点错位、和弦歧义、乐器误判、分轨串音、音源音色差异、改编接缝。区分模型缺陷与本项目数据/渲染错误。

用户应能完成至少一个实质音乐判断：讨论某段的和声或节奏，基于事件核对结论，做出修改，并通过试听判断是否达到要求。AI 不以修辞评价替代实际音频结果。

若整体识别误差使作品无法支持有意义的讨论，应改进模型/纠错流程或明确该素材能力受限；不能仅凭界面可用就宣布该曲还原完成。

## 必测失败场景

- 损坏音频、超出资源预算、模型访问失败、GPU OOM、磁盘空间不足。
- 分块缺失、重复边界音符、空转录结果、时长不一致、拍点不单调。
- 上传/任务 SSE 断线、AI 请求超时、取消后迟到的工具结果。
- 用户编辑与 AI 旧版本编辑冲突、编辑成功但渲染失败。
- 数据库事务中断、产物发布前崩溃、重启时存在过期任务租约。
- 循环边界的持续音/踏板、渲染尾音、试听模式切换和浏览器挂起恢复。

取消后的迟到结果可以保留为诊断记录，但不能自动改写工程当前版本。
