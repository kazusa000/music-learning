# 主页永久删除工程

2026-10-21。用户明确要求在主页添加删除按钮，彻底删除且不创建备份。

## 使用行为

主页每个工程行右侧有垃圾桶按钮，工程详情标题旁也有“删除工程”。点击后使用深色原生dialog确认，明确显示工程名、删除全部版本/讨论/专属音频且不可恢复；不提供备份开关。取消不写入。归档工程同样可删除。提交后显示取消任务/清理文件的状态；只有物理清理完成才显示已彻底删除。文件占用、路径异常等失败显示实际原因，并提供重试。刷新后未完成清理仍可见。

删除当前工程时停止主页试听、清除已过期详情缓存；删除最后一个工程清空localStorage选择与URL，回到空库。删除其他工程不改变当前歌曲。

## 统一接口与持久执行

projects.delete沿用project_id、expected_revision和幂等；返回ProjectDeletion。新增projects.deletions.list(Page)回读状态，共78操作，无新数据库迁移。API/SDK/CLI均从权威契约发现，schema/TS已重新导出。

在同一写事务中记录不含音乐内容的project.deletion.intent，保存项目/素材/任务等ID及状态计数。它不是工程备份，不保存快照、音符或讨论正文。正在运行的工程任务及对话先取消，等待实际终态后再删除记录。待删除工程拒绝新增编辑/任务，版本冲突仍拒绝删除；没有新增AI编辑权限开关。

工程表、全部内部与手动版本、分析、任务、讨论/会话、混音及关联投影在事务内删除；包含旧快照/讨论的命令回执也清掉，只保留小型删除回执用于幂等。原有events承载持久清理状态，不修改冻结迁移、不产生SQLite备份。worker在重启后继续等待或清理；失败停止自动重试，用户可用同一个projects.delete接口显式重试。幂等重放原回执，列表反映最新进度。

## 实际文件范围

只处理本工程已登记CAS及导入任务绑定的上传源、自己的任务/失败日志/讨论工作目录、按project_id或revision_id归属的原生请求和实时会话。当前工程、旧版本和导出所引用的专属文件均在候选内。其他工程关联、实际在用或仍处于保护期的另一份上传会保留；过期未使用上传不能永久保活已删除工程的文件。对应失效stage_cache也删除。

只在本地data_root的固定子目录中操作，检查父目录重解析点，工作目录递归不跟随联接。不会遍历删除外部原曲、音源库、模型权重或NAS。以前被拒清理的旧目录没有被本次测试或部署触碰。

上传CAS发布和上传登记放入同一SQLite写锁，并在线程中执行，防止删除与相同SHA的新上传竞争而出现成功登记但文件已消失。普通素材回收保留未完成删除的文件清单，不通过GC绕过失败状态。

实时会话持久保存归属与API进程身份。请求删除后关闭该工程的原生会话；编译/加载线程尚未退出时，清理等待cleanup_ready，防止删除后又写回插件资源。API已退出则其Job Object释放子进程，worker可以恢复清理。
