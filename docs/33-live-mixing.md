# 音轨即时混音与声音准备

2026-10-20。音量、声像、静音、独奏直接控制逐轨播放，停止拖动约400ms后合并保存。顶部“导出混音”生成最终WAV；日常调整不再要求点击生成试听。

## 播放与版本

`playback.get` 返回绑定目标revision的逐轨播放计划。仅从本版本和真实祖先中寻找完整、时钟一致、内容签名相同的音频；轨道事件、插件状态、控制器、自动化、路由和时间映射变化都会影响匹配。祖先音频中已烘焙的增益和立体声平衡由播放通道换算，已静音或丢失单侧声道的产物不逆向伪造。

浏览器每轨有独立增益、左右平衡和真实信号电平表，同一PCM素材也建立独立播放通道。推子更新不重启音源、不改变播放位置。只对新增或音频实际变化的通道替换播放源；解码缓存在不同通道间共享。播放不再用按所有声部峰值重新归一化的方式抵消用户推子调整，也不额外插入隐藏压缩器。原曲比较的电平匹配仍属于试听设置。

`mixer.set` 接受轨道的gain_db、pan、mute、solo、name，走统一Service、expected_revision、幂等与持久事件，创建独立音乐版本；没有变化时不制造空版本。有完整兼容声音时无需新任务，项目可标ready。ready在此表示目标版本可用逐轨实时混音；这不创建或冒充新Render。`renders.list`仍只列实际生成并绑定其revision的产物。

SDK提供`playback`、`set_mixer`，CLI可用`music.cmd call playback.get`和`music.cmd call mixer.set`，操作描述通过能力发现读取。契约现为57操作、11任务类型，无数据库迁移。SDK/AI/前端修改后的试听目标随最新版本更新；当前版本不会被错误锁成历史版本，历史回看仍只读。

## 更换乐器、改音符与最终导出

独立直达主输出的轨道，声音准备复用签名、宿主、音频实现依赖和尾音策略均匹配的逐轨产物，只实例化发生变化的VST3处理链；原生宿主仍组装最终处理结果。复用信息写入manifest/report，原快照和原插件状态不改写。预览准备的`project.render`使用`preview=true`，连续新修改取消本工程旧预览准备，显式渲染和导出不会被取消。

**目前不是常驻实时VST3引擎。** 新乐器和音符仍需后台原生生成声音，不能承诺像实时DAW一样立即出音。带总线、发送、侧链或混音自动化的工程不能从旧逐轨音频安全反算，自动回到原生处理图准备，接口会返回原因。此限制不假装为逐轨即时混音。

“导出混音”提交`project.export(format=wav)`。有目标版本完整混音时复用；否则在同一受fencing保护的导出任务内生成目标版本混音，再输出WAV。显式render_job_id仍校验工程和版本。试听可用不等于已存在最终混音文件，导出也不改变音乐head。

## 声部漏播与试听保存冲突修复

后续用户反馈电吉他没声音、反复出现`Expected revision differs from project head`。实际电吉他mute/solo均为false，音量约-13.3dB，4,545音符和声音文件存在；80–82秒PCM峰值约0.2105、RMS约-29.27dBFS。原因是旧`audition.mode=tracks`仅包含其余5声部，形成了独立于新混音台的隐藏筛选。已通过正式`audition.set`恢复mix并清空筛选，没有改音符或音色。

规则修复：UI操作音量、声像、静音/独奏时立即回到完整混音；Service的`mixer.set`同步移除tracks筛选，连“不改变音乐数值的取消静音”也有效，名称修改不清筛选。显式SDK声部试听仍保留，UI在工具栏收起时也显示“仅试听N/M声部、未播放声部”和“返回完整混音”。

混音保存和试听设置共用有序写入链；试听请求不再捕获过期head。`auditionSync.ts`仅对明确的revision_conflict读取最新head并有限重试，跟随当前版的试听目标随之更新，显式历史目标不变。新混音版本可能使旧position report失效；transport_superseded在观察回报中正常忽略，不再暂停实际声音。网络错误不自动重放，音乐编辑的expected_revision与观察sequence校验均保留。
