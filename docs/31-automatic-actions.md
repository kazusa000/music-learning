# 直接对话操作与上下文分离

2026-10-20。用户要求删除手动权限需求，并指出自己没有选择60–75秒片段。用户新要求优先于旧规划里的前端讨论/改编/结构权限开关。

## 原因与当前规则

旧UI点击“改编”会自动把上下文切到试听循环，随后只授权该区间，默认structural=false，因而换音色被拒绝。引用定位也会写入循环起止，之前浏览器验证曾在正式试听状态写过60–75秒；这不是用户这次的编辑要求。

现在没有“讨论/改编”切换和“允许结构编辑”复选框。dialogue.submit 新增 edit_mode，默认auto；当前版本的正常对话自动获得本工程全时段的制作能力。模型根据用户语义决定讨论还是执行修改，不要求用户再授权。用户要求换音色时，直接查询实际目录、捕获、提交新版本与整曲渲染。

选中音轨及讨论起止仅是定位上下文；默认整曲，只有主动从上下文菜单选择片段或点击“聊选中片段”才采用局部。用户明确指定的目标优先于界面焦点。换会话重置整曲，前端重试重新提交当前上下文，不重放旧UI的局部权限。

引用现在只定位视图/播放位置，不改变循环起止。正式旧试听循环已清为关闭、0至整曲末尾。只读浏览器检查通过 audition-sandbox.mjs 拦截 audition.get/set/report，在浏览器内模拟试听状态，不能再把测试选区留到正式工程；真实试听持久化的专门测试须用独立夹具。

位置引用可选，缺少引用或返回未知引用ID不再让整轮失败；未知链接不会变成可点击的工程定位，内部保留ignored_citation_ids。正常聊天和只查音色目录不强制提交编辑。真实编辑校验失败仍保留实际原因，不能伪装成提交成功。旧invalid_citation记录不改库，前端显示回复保留和链接不可用，不再输出长串英文错误。

## 接口与持久化

仍为55项操作、11类任务，无数据库迁移。Service计算自动scope保存到轮次context，原始请求payload保留；旧edit_scope显式调用仍受其自身约束。SDK/CLI可显式指定edit_mode=read_only，不能同时传编辑scope；历史版本讨论仍正常读取。跨工程、expected_revision、幂等、任务租约/fencing、素材摘要和新版本事务校验保持。自动模式新增默认字段从历史幂等摘要剔除，旧收据仍可回放。
