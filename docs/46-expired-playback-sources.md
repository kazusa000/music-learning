# 过期试听与当前工程加载

2026-10-21。用户主页出现 `assets record not found`，原曲长度、处理记录和打开入口一起消失。

## 根因与修复

正式HTTP逐项查询发现projects.list、revisions.get、preprocessing.get、jobs.list、versions.list、renders.list正常，只有playback.get失败。当前工程直接引用2697份素材，登记/文件/逐文件SHA全部通过，6轨9378音符完整。失败来自历史Render：旧试听被正常回收后，发布记录仍保留；复用逻辑在判定音轨内容相同时，直接要求已过期音频的assets记录存在，抛错使主页Promise.all整体失败。

playback.sources现在将历史派生音频的缺失登记、缺失项目关联、文件已回收视为复用未命中，继续寻找可用祖先；声部与其共用响度参考mix都必须有登记/项目关联/实际文件，随后仍执行完整SHA校验。内容损坏仍拒绝，音轨签名、Keyscape输入适配指纹、宿主/代码指纹、整曲边界和尾音要求不变。没有有效历史音频时返回实际pending声部，交给既有常驻逐轨流程，不伪装为完整Render，不自动排队整曲渲染。

这个规则同样用于播放计划、增量制作复用和素材保留规划，不针对某个歌曲、SHA或插件写特例。当前快照/手动保存版本必需素材的保留与缺失拒绝规则没有改动。

主页将加载错误与导入/归档等操作错误分开。完整刷新成功后自动清除过期的加载错误；后台刷新不会抹掉用户操作错误。
