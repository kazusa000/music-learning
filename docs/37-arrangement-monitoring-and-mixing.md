# 编曲监听、独立混音与播放启动

2026-10-20。用户要求把混音移到编曲结束后的独立环节。本约定覆盖此前在编曲页自动保存推子、默认匹配电平的交互。

## 使用边界

- 默认进入“编曲”。没有混音台、音量推子、声像或电平匹配；更换乐器、改音符、加轨仍走逐轨声音更新，不自动渲染整曲。
- 编曲页的独奏、静音只是本窗口的临时监听。立即作用于播放节点，不提交 `mixer.set`，不保存到音乐修订、混音配置或用户版本。关闭窗口后清除。旧工程中的基础 gain/pan 保留，不擅自改写既有作品。
- 在原曲、参考或筛选试听中操作监听按钮，切换到当前工程音轨；原录音本身不能独奏其中的 MIDI 声部。
- “混音”是独立页面：不显示卷帘、音轨制作与 AI 侧栏；推子和声像即时试听，但只有“保存混音”写入配置。返回编曲恢复编曲监听，不带回混音推子。
- “导出最终混音”仅在混音页提供；先保存当前混音草稿，再显式导出 WAV。首页播放器直接播放音频，不再等待整曲电平分析或自动改变响度。
- 现有 `mixer.set` 保留供旧客户端使用，但新的编曲页面不再调用它。内置对话提示要求换音色/音符/音轨时保持既有 gain/pan，不附带混音或响度处理。

## 持久化与统一接口

冻结迁移 `0009_separate_mixing.py` 新增 `project_mix_settings`，与不可变音乐 revision、手动 checkpoints 分离。混音配置使用自己的 version，不拿音乐 head 当混音保存锁。原音乐修订、原自动保存记录和旧音频全部保留；完整备份/恢复识别 0009。

统一 API / SDK / CLI 为 **67 操作、11 持久任务类型**：

| 操作 | 含义 |
| --- | --- |
| `mixing.get(project_id)` | 当前工程各轨混音值、独立 version；没有保存配置时使用既有基础增益/声像，静音与独奏默认关闭 |
| `mixing.save(project_id, expected_version, tracks)` | 手动保存；幂等、类型/音轨归属/独立并发校验；不创建音乐修订、checkpoint、Render 或任务 |
| `jobs.submit(kind=project.export, payload={format:wav, mixing_version:N})` | 固定音乐 revision 及混音版本，在提交事务内冻结各轨值；后台配置变化不会改变排队导出 |

显式混音导出使用单独的制作快照摘要，不覆盖编曲快照。不能复用一份不包含该混音配置的旧整曲文件；不会把它发布为原音乐版本的 Render。结果记录 `mixing_version`、制作快照 SHA 和原编曲快照 SHA。原生导出、任务租约、attempt fencing、素材与插件完整状态校验不变。

## 播放问题与修正

原故障包括：混音自动保存使用陈旧 head，失败又撤回本地设置；播放原曲时独奏不切换音轨；启动等待完整电平分析；预加载只保留声部别名却清掉底层素材缓存；慢 PCM 请求被反复丢弃；同一次暂停的重复处理清掉已预备的首块声音。

现在临时监听没有音乐保存请求。播放位置保存失败也不拆掉正在发声的节点。已运行 AudioContext 不重复 resume；相同声音的监听路由走同步快路径，不读文件、不等待准备。预加载保留别名对应的底层资产，并在没有 Render 时也预载原曲。

原生首块 PCM 先取齐，再启动共同播放时钟，保护起音和多轨同步。暂停后只预取当前位置的一块声音；重复暂停不清缓存。重播复用该块，后续继续流式处理。迟到的块按共同时间裁掉过去的帧、向前推进，不再每次跳转并重新丢掉整块。取消的播放即使随后收到 PCM 也不能复活。外部 SDK 同版本定位仍采用明确的目标位置，不能被“保持播放”逻辑忽略。

参考版本固定后复用已经解析的播放源，暂停/重播不再重复查询其整曲快照和播放计划；切换参考、丢失音轨会话或服务重连后重新解析。声音尚在启动时切换监听保留原播放意图。

后台页面补充：参考切换回归曾捕到一次时钟前进但两轨电平为零、重播后恢复；仅凭该观测不能确定唯一原因。常驻 PCM 的后续供声现由独立 AudioWorklet 的音频线程通知唤醒，不再依赖可被后台限流的网页 timer；保持原生 DSP 与逐轨增益不变，预取约 240ms。实际浏览器 `data-audio-clock=worklet`，两轨 PCM 块/样本号持续前进，参考切换和后台观测均有实际非零电平。只有不支持 AudioWorklet 的环境保留 timer 兼容路径，本机 Edge/IAB 已验证 worklet。

曲末停止也由音频线程通知触发，播放/暂停按钮在命令完成时同步状态，不依赖后台可能暂停的 requestAnimationFrame。最终 SDK 定位到 304.9 秒后自动停在 305.00000 秒、0 声音流、0 live 错误；参考缓存重播仍约 25.5ms 调度首块。证据追加 `worklet.json`；控制器单元补充音频通知唤醒且不创建窗口 timer 的检查。

首次载入插件/采样仍有实际装载时间，不能把缓存重播速度当作所有音色的冷装载速度。复杂路由的常驻支持边界沿用文档 36；本次未启动 Keyscape 实时实例或第二批验证。
