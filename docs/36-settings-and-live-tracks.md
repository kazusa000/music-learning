# 设置、手动保存版本与常驻音轨播放

2026-10-20。本次用户要求替代此前“音乐编辑后自动整曲渲染”的试听前提：日常编辑自动保存工作状态，版本列表只收录显式保存的快照；音轨声音直接进入实时混音，整曲 WAV 留给显式导出。

## 使用

- 主页右上角“设置”：默认 AI 模型、本机已有/应用独立登录、新试听的电平匹配。按需读取真实 Codex 模型列表，设置写入本地数据库，刷新和重启保留。讨论栏与主页设置共用默认值；不复制凭据。
- 工作台“版本”：输入可选名称并点击“保存版本”。音符、推子、音色和音轨增删自动保存工作状态，不自动添加保存版本。保存快照不创建音乐修订、不创建音频任务。
- 已保存的快照可以查看、比较并设为 A。没有完整混音文件时也可以用逐轨播放与当前工程 B 比较。
- 音量、声像、静音、独奏作用于 WebAudio 混音节点。音符变化更新常驻 VST3 实例；更换插件状态/资源只装载对应音轨的新实例，第一段 PCM 可用后交接，其他音轨不暂停。空音轨不发声。
- “导出混音”才执行 `project.export(format=wav)`，按需要生成最终整曲混音。旧显式 `project.render` 仍作为工程制作接口保留。

“保存版本”与内部 `revision_id` 分开：内部不可变修订继续用于自动保存、撤销、并发校验、讨论与素材定位，前端不再把每次内部提交列作用户保存版本。原数据、历史音频和旧讨论均保留。

## 实现与接口

冻结迁移 `0008_settings_and_versions.py` 新增 `application_preferences` 和 `project_checkpoints`，不改旧快照。升级前沿用数据库备份；完整备份/独立恢复识别 0008。

统一能力发现现为 **65 操作 / 11 持久任务类型**。HTTP `/v1/commands`、Python SDK、CLI 共用以下接口：

| 操作 | 行为 |
| --- | --- |
| `application.settings.get` | 返回默认值、已配置状态、设置版本、实际路径、分析模型与正在运行的 Keyscape 验证进度 |
| `application.settings.set` | 使用独立 `expected_version` 更新默认值；写入幂等，不要求音乐 head |
| `versions.list` | 仅列人工保存的快照，可分页 |
| `versions.save` | 用 `expected_revision` 与幂等键记录精确修订的名称/时间；不改变 head |
| `playback.live.open` | `project_id/revision_id/track_id/client_id/client_sequence` 固定来源，后台准备常驻音轨，立即返回会话与状态 |
| `playback.live.status` | 回读装载状态、generation、精确修订与音轨 |
| `playback.live.chunk` | `session_id/generation/sample/frames` 返回立体声 float32 PCM，最大 16,384 帧；不创建音乐修订、任务、Render 或混音文件 |
| `playback.live.close` | 关闭本会话拥有的原生进程树，不接触其他音轨或后台验证 |

`revisions.list` 保留为内部历史查询，和手动版本列表含义不同。设置默认模型/登录方式在幂等匹配后生效，不改变旧请求的重放结果。SDK 显式的模型与只读/编辑范围仍保留。

`arrangements.apply`、`mixer.set` 和前端手动编辑不再排队 `project.render(preview=true)`；AI 收据说明工作状态的实际提交结果，不将未生成的音频称为已渲染。更换音色的快捷草稿也已删除“生成整曲试听”要求。

### 常驻原生处理

新增独立 `ml_track_host.exe`，复用固定 JUCE 实现与插件装载校验，但不替换原 `ml_audio_host.exe`。VST3 处理全部在原生子进程中，Python 只负责控制与 PCM 传输。宿主保存插件实例、MIDI/CC、源样本时钟、插件参数/自动化与延迟补偿；跳转会重置声音并追踪当时的控制器/持续音符。

普通音符编辑发送小型增量，避免重新编译/传输整首 9,378 音符的图；参数变更在兼容链中直接回写。结构或资源变化只重开该轨。老 generation 的请求及编辑期间跨代返回的 PCM 被拒绝，不冒充新内容。冷启动期间连续编辑也必须等最新内容装好才能标 ready。

浏览器通过共同 AudioContext 时钟调度约 93ms 的小块，约 120ms 预取；逐轨推子/声像/静音/独奏与原有混音节点共用。装载不阻塞 SQLite 写事务或其他轨的音频。窗口关闭、服务退出、会话闲置会清理自有原生进程；页面使用轻量会话心跳，服务重连后重新建立会话。插件崩溃/超时作为该轨失败显示，不能无限重试同一个坏进程。

可复用旧逐轨音频仍与精确内容/来源对应。查找旧声音改用只读递归祖先查询：只读取有音频发布的祖先快照，避免每次编辑都重新载入所有自动保存历史里的整曲音符。

构建新增宿主（先具备原有固定 JUCE 静态运行库）：

```powershell
& runtime/tooling/Scripts/python.exe scripts/build_live_host.py
```

独立工作树可加 `--runtime-root E:\Intrest\music-learning\runtime` 读取已存在的编译工具和静态库，输出仍在当前工作树。构建前关闭使用这个新增宿主的自有测试服务；不关闭 Keyscape 验证器。

## 实际边界

当前常驻轨通道支持直达主输出的独立立体声音轨。总线、发送、侧链与混音自动化仍由已有原生离线图完成，不能宣称它们也已接入此常驻通道；编辑不会因此偷偷生成整曲试听。插件自动化支持按源样本处理，但复杂链的持续实时负载需逐插件验证。

首次载入音色库仍需要该插件自己的装载时间。Keyscape 固定适配器已有 10 秒样本稳定等待，本次为保护正在运行的全量验证，没有另开 Keyscape 实时实例或第二批验证，不能把 sfizz 的速度外推到 Keyscape。新声音未就绪时保留旧声音和其他音轨播放。

实时音频与工作状态持久化分开计时。本机 305 秒、9,378 音符 sfizz 夹具：两轨冷装载约 0.75/0.83 秒，音符提交约 0.609 秒，已装载音轨的增量更新约 0.047 秒；8,192 帧取样请求约 0–16ms（系统计时精度）。这些是本机单次观测，尚不能承诺所有编辑均达到低延迟硬件 DAW 的响应。
