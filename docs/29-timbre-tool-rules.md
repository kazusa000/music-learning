# 音色查询与编辑工具规则

2026-10-20。用户反馈对话中推荐清音电吉他、切换改编后仍未执行，并明确要求修正规则而非写入针对该问题的答案。

## 实际失败

只读回读正式讨论记录：首次是讨论模式，没有编辑权限；后续已开启整曲 structural 权限，AI 的 production_query 传入了此前不支持的 track_id，music_edit 又使用 type 代替 op，并把 preset_id 直接放入 patch_plugin，未先捕获预设，服务正确拒绝，没有提交新版本。

该两轮实际选择的是指奏贝斯轨（Swag Finger Bass），模型却继续按电吉他说话。此前 UI 只显示“指定声部”，不容易发现。实际安装目录的 electric-guitar 分类当前只有一个已验证 Shiny Electric；模型推荐的 GM 编号不是独立已安装预设。搜索 clean electric 无结果也不等于全目录没有电吉他。

## 通用修正

- 普通讨论和改编都开放只读 production_query，先查安装目录再推荐具体音色。按 instrument_id 发现实际音色；关键词未命中时须回到分类查询。区分模型 GM 标签、分类、预设，不把同一预设改名说成换音色。
- production.query 新增可选 track_id，统一 Service/API/SDK/CLI。过滤轨道、插件、自动化和分配建议；未知音轨、插件与音轨冲突明确拒绝。对话查询默认沿用选中音轨，保留显式查询其他轨的只读能力；写入权限仍是原 edit_scope。
- 新轮次固定 selected_track 的版本内轨道身份；意图与选中音轨冲突时明确指出，不能借自然语言扩大编辑范围。输入区与历史轮次显示音轨名称，旧记录保留并尽可能按 ID 显示。
- 工具说明提供有效的编辑格式和完整预设流程：查询目录 → preset_capture → 成功后以 preset_capture_job_id 提交 patch_plugin → 新版本与整曲渲染。讨论模式说明如何切换改编，不把单轮只读说成应用没有编辑能力。
- music_edit 格式失败返回由同一契约生成的操作标签及匹配操作 schema，覆盖所有编辑操作。允许修正失败请求后在同轮重试；不自动改写用户/模型参数、不放宽校验、不扩大权限。预设错误说明与 schema 错误分别处理。

仍为 55 项操作、11 类任务，无数据迁移。已导出 schema/TS；源录音、原始输出、历史讨论和正式工程版本未重写。
